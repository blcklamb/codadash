# keybit 요구사항 명세서

문서 v1.0 · 게임 규칙/콘텐츠 버전 1.0.0 · 2026-09-10

## 1. 적용 범위와 기본값

- 지원: JavaScript, TypeScript, Java, Rust, Go, Python, C, C++, C#, Swift, Bash.
- 모드: 속도 측정, 일일 도전, 초대형 1대1.
- UI: 한국어·영어. 저장된 선택 → 브라우저 한국어 여부 → 영어.
- 실제 플레이는 데스크톱 중심. 모바일은 소개·계정·기록 조회.
- 비회원 가능, GitHub 로그인 선택. 공개 순위·랭크·채팅·결제·코드 실행 제외.
- 기본 언어 JavaScript, 난이도 입문, 시간 60초. 이전 선택 기억.
- 개인 기록은 같은 모드·언어·난이도·시간·규칙 버전에서 비교한다.

## 2. 입력 판정 INP

1. ASCII 코드의 대소문자·기호·줄 안 공백·줄바꿈을 정확히 구분한다.
2. 줄 시작 들여쓰기는 정답 화면에 유지하되 자동 처리하고 입력 수에서 제외한다.
3. 내부 줄바꿈은 Enter 1회. 마지막 줄 뒤 Enter 없이 완료한다.
4. 끝에 입력하거나 Backspace로 삭제한다. 커서 이동·선택 치환·자동완성·자동 괄호 닫기는 없다.
5. 오타는 빨간색과 밑줄, 정답은 완료색, 현재 위치는 커서로 표시한다.
6. 오타 이후 입력 가능하나 앞선 오타가 남아 있으면 유효 진도는 오타 직전에서 멈춘다. 전체 정답과 일치해야 다음 코드가 된다.
7. 붙여넣기·드래그 입력은 차단한다. IME 조합은 판정하지 않고 영문 전환을 안내한다.
8. 포커스 이탈에도 타이머는 계속 흐른다. 입력 수집은 플레이 입력 영역에서만 한다.

## 3. 기록 MET

- 완료 블록: 시간 내 정답 전체와 일치한 블록 수.
- 유효 문자 C: 완료 블록의 대상 문자 + 현재 블록에서 처음부터 연속 일치한 문자.
- CPM = round(C × 60 / 측정 초). WPM은 CPM / 5인 보조 지표.
- 정확도 = 입력 순간 정답 위치와 맞은 횟수 / 전체 문자 입력 횟수 × 100, 소수 한 자리.
- 입력이 없으면 CPM 0, 정확도 없음(—).
- 공백·직접 Enter는 각각 1문자. 자동 들여쓰기·Backspace·조작 키 제외.
- 삭제·재입력은 C를 중복 증가시키지 않는다. 삭제해도 이전 오류는 정확도에 남는다.
- 부분 블록의 유효 진도는 CPM에는 포함하고 완료 수에서는 제외한다.
- 최고 CPM이 같으면 정확도를 비교한다.
- 언어마다 블록 길이가 다르므로 서로 다른 언어의 완료 수로 실력 순위를 매기지 않는다.

## 4. 속도 측정 SPD

시간 30/60/120초, 난이도 입문/일반. 3초 후 코드 공개와 타이머를 동시에 시작한다. 완료하면 다음 블록이 즉시 나타난다. 일시정지·건너뛰기 없음. 중도 종료는 완료·최고 기록에 반영하지 않는다.

결과: 블록 수, CPM, 보조 WPM, 정확도, 유효 문자, 동일 조건 최고 기록과 차이, 5초 구간별 CPM, 오타 문자 상위 3개. 같은 설정 재도전 또는 설정 화면 복귀.

## 5. 일일 도전 DLY

- 언어별 매일 하나, 입문·60초 고정. 서버 날짜·언어·버전으로 코드 순서 결정.
- 매일 Asia/Seoul 00:00 갱신. UI 언어와 관계없이 동일. 다음 갱신까지 남은 시간 표시.
- 자정에 걸친 세션은 시작 날짜에 귀속한다. 그 날짜의 콘텐츠 버전은 고정한다.
- 60초 완료 + 최소 1블록 완성이 출석 조건이다. 무입력·중단은 출석 불인정.
- 무제한 재도전. 해당 날짜·언어 최고 CPM을 보여주며 동률이면 정확도 우선.
- 여러 언어를 해도 같은 날짜는 연속일 1일만 인정한다.
- 현재 연속일, 최장 연속일, 최근 30일 달력.
- 오늘 아직 완료하지 않았더라도 어제까지 이어진 연속일은 오늘이 끝날 때까지 유지한다.

## 6. 방 ROOM

- 서버가 무작위 6자리 영문 대문자·숫자 코드를 만든다. 0/O/1/I 등 혼동 문자 제외.
- 닉네임 2~16자. 코드나 초대 링크로 최대 2명 입장. 닉네임을 인증 수단으로 쓰지 않는다.
- 같은 계정/게스트는 한 자리만 점유한다. 다른 플레이 중이면 새 세션 생성 불가.
- 방장만 언어·난이도 설정. 설정 변경 시 두 명 준비 해제.
- 둘 다 연결·준비 상태이면 3초 후 시작한다.
- 대기실 15분 무활동 만료. 대기 중 방장 이탈 시 남은 사람에게 이전.
- 코드 오류, 없음, 만료, 정원 초과, 경기 중, 중복 참여를 구분한다.
- 참가자 토큰으로 자리 복구 권한을 확인한다.

## 7. 산성비 대전 PVP

### 기본 규칙

경기 최대 120초, 체력 각 5. 같은 언어·난이도·기본 코드·생성 시각·낙하 시간을 공유한다. 코드를 정확히 완성하면 제거한다. 바닥 도달 1개당 체력 1 감소. 오타 자체는 피해를 주지 않으나 공격 콤보를 초기화한다.

| 난이도 | 한 줄 길이 | 0~~40/40~~80/80~120초 생성 간격 | 같은 구간의 낙하 시간 |
| ------ | ---------- | ------------------------------- | --------------------- |
| 입문   | 8~18       | 4.5/4/3.5초                     | 16/15/14초            |
| 일반   | 12~28      | 4/3.5/3초                       | 12/11/10초            |

서버 시간으로 판정한다. 창 크기는 바닥 도달 시각을 바꾸지 않는다. 화면에서 코드끼리 겹치지 않게 배치한다.

### 대상 선택

가장 먼저 바닥에 도달할 코드를 기본 선택한다. 입력 시작 후 대상 고정. 빈 입력창에서 ↑/↓로 선택한다. Escape로 입력을 비우며 오류 기록은 유지한다. 대상이 바닥에 닿으면 입력창을 비우고 체력을 차감한다. 자동선택·피해는 서버와 클라이언트가 같은 상태를 보아야 한다.

### 공격

- 기본 코드 3개 무오타 연속 완료 → 상대에게 추가 코드 1개.
- 오타가 있었던 블록은 수정 완료해도 무오타 콤보에 포함하지 않는다.
- 오타·낙하 실패는 콤보 초기화. 공격 코드 제거는 콤보 증가 없음.
- 공격 간격 최소 8초, 수신 공격 코드 동시 최대 2개.
- 1초 예고 후 생성, 해당 난이도 현재 낙하 시간 적용. 놓치면 체력 1 감소.
- 공격 조건 달성 시 콤보 초기화. 쿨다운/수신 상한 때문에 못 보낸 공격은 적립하지 않는다.
- 공격은 기본 코드 생성 순서를 바꾸지 않는다.

### 승패

1. 한 사람 체력 0 → 상대 승리.
2. 같은 서버 주기에 양쪽 체력 0 → 무승부.
3. 시간 종료 → 체력, 기본 코드 제거 문자 수, 정확도 순 비교.
4. 모두 같으면 무승부. 공격 코드 제거량은 동률 문자 비교에서 제외.
5. 결과에 판정 이유·양측 통계·공격 수·재대결을 표시한다.
6. 둘 다 동의하면 같은 설정, 새로운 순서로 재대결한다.

### 연결

게임은 연결 중단 시에도 멈추지 않는다. 10초 내 복귀하면 현재 서버 상태로 계속한다. 한쪽이 10초를 넘기면 기권패, 양쪽 모두 끊긴 상태에서 복귀 제한 초과면 무효. 이미 끝난 승패를 이후 연결 상태로 바꾸지 않는다. 서버 상태를 잃으면 무효 처리한다. 복구 중 입력을 받지 않는다.

개인 연습도 타이머를 유지하고 10초 내 복귀하지 못하면 중단 처리한다.

## 8. 콘텐츠 CNT

550개 서비스용 원본 코드 조각: 언어별 입문 블록 10 + 일반 블록 10 + 입문 한 줄 15 + 일반 한 줄 15.

블록 입력 대상: 입문 40~~100자·2~~4줄, 일반 100~~200자·3~~6줄. 의미 있는 들여쓰기 보존. ASCII 중심, 장문 주석·난해한 문법 제외. 완결된 실행 프로그램이 아니라 문맥 안의 코드 조각이다. 실행하지 않는다.

ID, 언어, 난이도, 용도, 원문, 대상 문자, 버전 관리. 연습은 한 덱 내 중복 없이 섞고, 일일 도전·대전은 서버 시드로 순서를 고정한다. 대전 기본 코드의 연속 5개에 같은 문구 없음.

## 9. 기술·인터페이스

React, TypeScript, Vite, Tailwind CSS, React Router, i18next, TanStack Query. Node.js LTS, Express, Socket.IO, Zod. Supabase Auth GitHub와 PostgreSQL. 단일 게임 서버 메모리에서 실시간 상태를 관리하고 시작·종료·결과를 DB에 저장한다.

- GET /v1/catalog
- POST /v1/guest-sessions
- POST /v1/practice-sessions
- GET /v1/daily-challenges
- POST /v1/rooms
- POST /v1/rooms/join
- GET /v1/me/records
- GET /v1/me/bests
- GET /v1/me/activity
- GET /healthz

실시간: attach, input, command → practice, room, battle, result, saved, notice.
입력 명령은 순서 번호와 단일 문자·조작을 보낸다. 서버가 중복 제거·정답·타이머·체력·공격·승패를 검증한다. 클라이언트 입력 피드백은 즉시 반영하고 서버 스냅샷으로 보정한다. 서버 주기 20Hz, 상태 전송 최대 10Hz. 재접속은 전체 상태 재동기화. 과거 입력 시각으로 판정을 되돌리지 않는다.

브라우저가 제출한 점수·승패를 그대로 저장하지 않는다. 자동 타자 탐지를 완벽하게 보장하지 않는다.

## 10. 기록·권한·운영

- 게스트 기록은 기기 브라우저에 보존. 로그인 후 새 기록은 계정에 보존. 자동 합산 없음.
- 본인 기록만 조회. 서버 전용 키는 서버에만 배치. 토큰·전체 입력을 로그에 남기지 않음.
- 결과 저장은 사용자·세션 조합으로 중복 제거. 실패 시 재시도, 확인 전 저장 완료 표시 금지.
- 브라우저 저장 실패도 명시한다. 로그인이 미설정되어도 게스트 플레이는 동작한다.
- 서버 종료 시 신규 세션 중단, 최대 180초 기존 경기 종료 대기. 재시작 시 미완료 세션 중단 처리.
- 요청 크기·속도 제한. 계정·결과 데이터의 RLS와 소유권 검증.
- 정적 프런트 Cloudflare Pages, Node 서버 Render, 인증/DB Supabase. 초기 예산 월 5만 원 안팎.

## 11. 검증과 완료 조건

단위 테스트: 오타 수정, 삭제 재입력, 부분 블록, 시간 경계, 중복 명령, IME 차단, 날짜 경계, 연속일, 550개 콘텐츠 조건, 공격 조건/상한/쿨다운, 승패·연결 예외.

통합: 두 독립 세션의 방 생성·입장·준비·대전·재접속·재대결·기권. 권한 없는 자리 복구·기록 조회 거부. 결과 저장 중복 방지.

브라우저: Chromium, Firefox, WebKit 주요 흐름. 실제 Safari·Edge 최종 수동 확인 별도. 데스크톱 1280×720 이상, 모바일 조회 360px 이상, 키보드 접근, 언어 전환, 모션·소리 설정.

성능: 입력 시각 반영 p95 50ms 목표. 대전 20방/40명 + 개인 연습 10명, 30분에 상태 혼선·중복 결과 없음. 서버 이벤트 처리 p95 50ms 목표. 왕복 지연 100ms 환경의 두 화면 최종 판정 일치. 로컬 결과와 실제 배포 환경 결과를 구분한다.

출시 완료는 기능 구현, 자동 검증, 실제 계정 저장 확인, 실제 배포 확인을 모두 충족할 때로 정의한다. 외부 키나 서비스가 미설정된 부분을 동작 확인한 것으로 보고하지 않는다.
